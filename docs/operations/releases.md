# Bridge releases

The repository-to-image allowlist is [`.github/bridge-publishers.json`](../../.github/bridge-publishers.json). It identifies existing packages; repository entries alone do not grant registry access.

Keep Changesets entries and changelogs inside the six existing pnpm/Changesets bridge directories. Prepare a version PR from the owning directory, using its pinned `pnpm changeset version` command and reviewing the resulting package version, changelog and lockfile. Do not run it from the website root or combine unrelated version PRs. For Display and Modbus, review the Cargo package version, lockfile and the matching bracketed changelog entry together. For AdGuard Home, review its package version and changelog. Never auto-merge version PRs. Ping has no package publisher.

After the version PR is merged, tag the reviewed main-branch revision as `<slug>/v<major>.<minor>.<patch>`. Use **Bridge release** from `main`. `dry-run` is the default: it validates the tag and builds one linux/amd64 image and any binary release artifacts without writing to the registry. `handoff-test` uses a unique non-production tag on the existing package and never moves `latest` or creates a release. `release` publishes that bridge's tested image, established aliases, scoped notes, and applicable assets. The Modbus archive retains its existing filename, layout, and SHA-256 sidecar.

Set `BRIDGE_RELEASE_PACKAGES` on the `bridge-release` environment to a JSON array of approved slugs. A maintainer starts the workflow manually from `main` and selects a mode; an authorized publish proceeds without a second deployment approval. Keep the environment restricted to the `main` branch. A missing or empty allowlist must block writes. Do not grant the workflow organization-wide credentials. If publishing fails after an immutable version was pushed, compare the registry digest with the tested artifact, complete only the missing aliases or release assets under separate approval, and record the partial result; do not rebuild and overwrite a published version.

Before the first push, `release` reads the selected package's complete version listing. Each existing alias must identify one stable immutable version under that bridge's tag convention; the release may not move the alias backward. Missing version evidence, conflicting tags, or an already published immutable tag blocks the entire push. This check is serialized within the release workflow, not against outside publishers: keep a single authorized writer.
