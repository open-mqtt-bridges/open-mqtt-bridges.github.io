# Capture and restore a source

Use a private directory outside every checkout with sufficient free space. Do not run garbage collection on sources during inventory. A repository administrator is a contact, not proof that every maintainer has disclosed local work.

1. Record the source URL, observed default branch, all known local clones and worktrees, and the cutoff. Compare advertised branches and tags, GitHub's paginated open/closed PR list, available `refs/pull/*`, fork tips, and known source pins (including the open documentation branch). Record the PR head OID even if the branch or fork disappeared. Distinguish the synthetic advertised `/merge` ref from a PR's historical merge result. Include both when observed. Record undeclared clones, unavailable objects, and uncommitted work as open questions, not zero counts.
2. Prepare a private JSON object with `source`, `defaultBranch`, `clones` (absolute paths), and `knownTips` (objects with `ref`, original `oid`, and optional `from` repository containing it). Never put credentials in URLs. Include entries for every independently inventoried head, tag, PR, and gitlink pin, even when redundant. Mark stale and detached local worktrees; inspect local changes separately with their owners.
3. Run `node scripts/migration/snapshot.mjs PRIVATE-CONFIG.json NEW-PRIVATE-DIRECTORY`. It inventories source refs, anchors local and additional objects in a private mirror, writes `refs.json` and `expected.txt`, bundles all refs, restores them in an empty repository, compares refs/commits, and inspects historical trees and LFS pointers. A failed directory is incomplete; retry in a new directory without replacing the evidence. Archive the original input and GitHub listings with the resulting private backup.
4. For every reported gitlink, locate its original URL at the referencing revision, capture the child repository and required OID, and verify restoration recursively. For LFS, fetch and back up the actual content, then verify each restored file against its pointer SHA-256. Back up GitHub release assets separately and check their digests. A successful Git bundle does not establish any of these external checks.
5. Store an independent private backup copy outside the rehearsal environment and rehearse restoring from it. Publish only reviewed aggregate evidence. Private, unreachable, or PR-only material must be reviewed before target publication. A missing known OID, missing asset, unknown local coverage, or unresolved publication rights stops acceptance. Freeze and recapture before actual cutover.
