# Production cutover

The PR prepares the migration. The [status record](../../migration/cutover-status.md) distinguishes rehearsed checks from completed production operations. The organization administrator coordinates the window with the source owners listed in [the inventory](../../migration/sources.json). Keep a private evidence directory with immutable copies of the manifests, bundles, release assets, and reports. The original website, bridge histories, and package permissions must remain recoverable.

1. **Agree on scope and freeze.** Obtain separate approval for the production merge, public recovery refs, each package handoff, and eventual archival. Announce the write freeze. Inspect remote heads, tags, all PRs, local worktrees and source pins again. Include new work and newly discovered objects. Resnapshot any changed sources and rerun their import, CI, and full-clone verification; never rewrite original OIDs or replace a recorded ref silently. Keep unrelated documentation work on its own branch. If an unreviewed delta affects the approved PR, stop and return it to review.
2. **Review public disclosure.** The private rehearsal includes recovery-only commits not reachable from inventoried public refs. Specifically review author data, local-only revisions, PR refs, historical files, and credentials. A private rehearsal or clean automated scan does not authorize making them public. If any known object cannot be released, retain the private evidence and stop; do not claim a complete public migration or substitute rewritten history.
3. **Prepare target rules.** Record target settings and verify Actions state, active rules, required reviews and successful current-head checks. Verify the exact reviewed head SHA and approved base. The merge must preserve parents: GitHub **Create a merge commit**, never squash or rebase. Keep original immutable tag objects. Plan durable rules against deletion/force-push for archive heads and tags and restrict which principals may change them. Do not proceed with overlapping writers.
4. **Transfer only approved refs.** Disable workflow execution on the production target for the historical ref transfer using a separately approved, scheduled window. Confirm no in-flight writes. Prepare a dry-run with explicit namespaces `refs/heads/import/*`, `refs/tags/import/*`, and `refs/tags/recovery/*` from the verified private integration clone. Check destination OIDs, new names, limits and collisions before an atomic non-forced push. Do not push `--mirror`, local branches, other refs, or pending work. Restore the target's original Actions settings after the transfer, verify archive rules, and recheck required CI for the final feature head before merging. Coordinate the website's normal Pages workflow on `main`; do not repoint individual guide hosts.
5. **Prove the actual merge.** Save the merge OID and create a new full HTTPS clone of the public target. Fetch its heads and tags without alternate object stores or source remotes. Use the source-specific private snapshot plus the original import record with `targetBranch` set to `main` for `node scripts/migration/verify.mjs <clone> <snapshot> <record.json>`. Require zero missing original commits, exact original ref OIDs, both import parents and identical source trees for all eleven sources. Repeat the live guide and release links, download and digest probes. Stop on any failure; do not advance package ownership.
6. **Switch publishers individually.** Follow the [package handoff](package-handoff.md). Capture before/after package ID, visibility, reader access, old and new grants, digests and run URLs. Pause the old publisher and complete each handoff before moving to the next package. Do not activate a publisher for Ping or IDM Energy.
7. **Update contributor entry points.** Merged catalog source links point at `tree/main/bridges/<slug>` or `tree/main/archive/idm-energy`; documentation URLs remain at their existing destinations. Probe the published targets first. Then run `node scripts/sync-profile.mjs ../.github` in the synced website checkout and review both marker-delimited organization README edits in a separate profile PR. Reconcile any concurrent profile or feature 902 change; do not overwrite new rows. Give each active source a relocation notice. Cross-link outstanding PRs, transferred issues, and historical release assets. Do not delete the originals.
8. **Observe or roll back.** Keep previous publishers recoverable for at least one regular release or operating cycle. If a bridge fails, pause the new writer, preserve post-cutover updates, restore the previous source association and grants, verify the old digest and resume only the old writer. Restore prior Pages output only if needed. Correct the target via normal commits, never a `main` reset or force-push. Do not archive a source that still serves a required route or asset. Archive only after recorded owner approval.
