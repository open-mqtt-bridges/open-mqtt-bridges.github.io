# Contract: Preserve the original Git history

## Capture the source

1. Use full source clones at the agreed cutoff. Inventory default and side branches, lightweight and annotated tags, available GitHub PR refs for **open and closed** PRs, and known fork tips. Label synthetic PR test merges separately and preserve their observed OIDs. Recover known missing PR objects from forks, local clones, or backups; stop if recovery fails. Back up the target's existing history as well.
2. Ask maintainers to identify local clones and worktrees. Before garbage collection, check unpublished branches, detached HEADs, stashes, reflogs, and remaining unreachable commit objects. Anchor recovered commits with durable refs. Uncommitted changes are not Git history: coordinate a separate backup with the owner and do not silently discard or publish them. Private content blocks publication until reviewed. Git cannot enumerate commits that have already disappeared from all sources.
3. Preserve the exact guide source pins delivered by feature 902, including any Display and Modbus gitlink OIDs, even when they differ from current branch tips. A gitlink stores only an OID. Back up referenced submodule objects and LFS content separately and verify they can be retrieved.
4. Once all objects are anchored, create a self-contained Git bundle and manifest per source. Derive the expected commit list from the **recorded source refs**, independently of the target. Restore the bundle into an empty repository and verify the expected set. Back up LFS data and release assets separately. A mirror clone alone does not establish PR or local commit coverage.

## Map refs and import the tree

- Map branches to `refs/heads/import/<slug>/heads/<old-name>`, PR tips to `refs/heads/import/<slug>/pr/<number>/head` or `/merge`, and additional local tips to a distinct namespace with unique identifiers. Anchor historical gitlink pins as well. Map tags to `refs/tags/import/<slug>/<old-name>` pointing to the **same object ID**. Validate names, file/directory conflicts, and fetch behavior in advance. Protect archive refs from force-pushes and deletion.
- Prevent write-capable workflows from running on `import/**` pushes. Historical branch tips can contain their own workflows. Disable Actions in the disposable target before transferring refs; agree on and test an equivalent safe transfer procedure for the real target.
- Start each import from a clean, isolated branch at the intended target base with an unused prefix and the source tip available locally. Begin a two-parent merge using `--allow-unrelated-histories --no-ff -s ours --no-commit`. Insert the complete tree into the prepared index with `git read-tree --prefix=<target-path>/ -u <source-tip>`, then create the merge commit. The `ours` strategy alone does not import any files. Check both parent OIDs and the prefix tree before making documentation, CI, or path changes in later commits. If the histories already overlap, still require the specified two parents; do not accept an accidental no-op.
- Integrate only the default source tips as product code. Other snapshots remain available through archive refs without merging unfinished changes into `main`. Old commits retain their old paths. Explain how to inspect pre-import file history from the second parent using the original path.
- Transfer the verified graph using an ancestry-preserving merge or fast-forward. **Do not squash or rebase the final PR.** If linear-history rules prevent the import, obtain and test an approved path or stop. Do not use `push --mirror` against the target: it can delete unrelated target refs.

## Independent acceptance test

Use a fresh full network clone of the target without source remotes, alternates, or local object reuse. Require an exact OID match for every archived ref, **zero** missing source commit IDs among reachable target commits, the integrated source tip as an ancestor of the target default branch, and an identical source and prefix tree at the import commit. Check Git integrity, LFS retrieval, and remaining submodules separately. Repeat after the actual merge and retain the report with the source snapshot and target OID.
