# Dependency research

- **Ping**: The lockfile already includes `rustls-webpki 0.103.17`, but `rumqttc 0.25.1` separately requires `^0.102.8` through `use-rustls-no-provider`. The crates.io index has no newer stable `rumqttc`. A lockfile-only update cannot remove the old instance. Turning the feature off would break the bridge's custom TLS configuration; retain it.
- **Display**: `ddc-hi 0.4.1` expects `mccs-db ^0.1.1`; `mccs-db 0.1.3` pulls `serde_yaml ^0.7`. `mccs-db 0.2.0` uses `serde_yaml ^0.9` but changes its MCCS dependency family and is outside `ddc-hi`'s range. The existing audit reports that the older parser receives bundled monitor data, not bridge input. A patch must verify that the bundled data still parses and control mappings are unchanged.
- **IDM**: #19 and #20 resolved vulnerable `ip-address`, `axios`, `follow-redirects`, and `form-data` versions. Reconcile #22 and #23 before editing the lockfile. `glob 11` still requires `minimatch 10`, which is insufficient for the current advisory. Published `rimraf 6.1.4` keeps the same major and depends on `glob ^14.0.3`; its engine requirement is `20 || >=22`, compatible with the archive's Node LTS build. Retain existing Node and Yarn ownership.
